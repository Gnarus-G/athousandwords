# OpenCode setup

Goal: Make the visual companion available to OpenCode on this desktop.
Done when: the companion is active and enabled, OpenCode reports its MCP connection
as connected, and the proactive visual instruction is part of the installed config.

## Installed

- OpenCode version: 1.18.35.
- Scope: global OpenCode configuration on the dotfiles `home` profile only.
- MCP name: `athousandwords`; local stdio command uses this checkout's
  `target/debug/atw` and a private connection file at
  `~/.local/share/athousandwords/opencode.atw.json`.
- Workspace: “OpenCode on home.” Sessions using this configured entry share it;
  this setup does not claim automatic per-conversation workspace isolation.
- Service: `athousandwords.service`, active and enabled under the user systemd
  manager. It listens on `http://127.0.0.1:7331` and automatically opens the
  dedicated desktop app on publication when needed, rather than a browser tab.
- Desktop entry: “A Thousand Words” in the application launcher, linked through
  the home profile. It invokes `atw open`, which reuses or raises the app window.
- Instructions: preserved `~/.pi/agent/APPEND_SYSTEM.md` and added this checkout's
  `docs/visual-communication-instruction.md` to the home OpenCode overlay.
- A sample Mermaid visual, “OpenCode can show ideas,” is saved at revision 1.
  Its state was accepted with no viewer connected, not claimed rendered.

## Activate in the running OpenCode session

Quit and restart OpenCode when reloading its tool descriptions and instructions.
The installed backend's automatic opening works through the existing connection.
To open or raise the desktop app explicitly:

```sh
/home/gnarus/d/athousandwords/target/debug/atw open
```

The user service starts on subsequent user-manager/login starts. After rebuilding
the application, restart it with `systemctl --user restart athousandwords.service`.
The app is keyboard-first: Ctrl K searches, ? lists shortcuts,
[ / ] selects revisions, and c / Ctrl Enter writes and sends a comment.
